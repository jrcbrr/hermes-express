     Stage 6: Tracking, barista queue, sold-out toggles

     Context

     Orders can be placed (Stage 5), but nothing moves them forward:
     /orders/[id] shows a static status and /barista is a placeholder. This
     stage lets staff advance orders, lets customers watch that live, and lets a
     branch mark items sold out. Branch: stage-6-tracking, from an up-to-date
     main.

     What already exists, so it won't be rebuilt:
     - src/lib/order-status.ts: statuses, canTransition, nextStatuses, already
       tested. Pickup and delivery paths are already correct; it only needs
       additions.
     - getOrderForUser already enforces owner / branch staff / admin, returning
       null for both "not yours" and "doesn't exist".
     - ReceiptView + buildReceipt, useSound().play("ding") (silent until
       Stage 8), soldOutCheck.
     - placeOrder already rejects sold-out items through the catalog snapshot.
     - Schema: order_status_event and branch_stock exist. No migration or new 
       dependency is needed.

     Build

     Pure logic (src/lib)

     - order-status.ts, add: advanceStatus(status, fulfillment) (the one forward
       move, never Cancelled), ACTIVE_ORDER_STATUSES, isFinalStatus,
       trackerSteps(fulfillment), trackerStepIndex(status, fulfillment). Extend
       tests with a full from/to/fulfillment matrix.
     - roles.ts, add: canManageBranch(user, branchId): admin always, barista
       only for their own branch.
     - New order-queue.ts: groupQueue(orders) (groups by status, soonest due
       first, using scheduledFor ?? createdAt) and findNewOrderIds(knownIds, 
       orders) (for toasts).

     Server (src/server)

     - orders/queries.ts: getOrderTracking(id, user) (status, fulfillment, event
       history, via getOrderForUser); listBranchQueue(branchId) (active orders
       with items).
     - New barista/actions.ts:
       - advanceOrder(orderId, to): Zod, requireRole(["barista","admin"]),
         canManageBranch, canTransition.
       - The status update and event insert are one SQL statement (WITH moved AS
         (UPDATE ... WHERE status = <from> RETURNING ...) INSERT INTO 
         order_status_event ...). If two baristas tap together, only one wins
         and exactly one event is written. A plain db.batch could write a
         duplicate event. The loser sees "This order was just updated."
       - An order at another branch returns the same message as a missing one.
         Owning an order gives no right to advance it, so a barista who is also
         the customer at another branch can only view.
       - setSoldOut({ kind, itemId, soldOut }): upserts branch_stock for the
         caller's branch only, validates that the item exists, then calls
         updateTag(CATALOG_CACHE_TAG). Without that call, customers would see
         stale stock for up to an hour.
     - New barista/branch.ts: resolveStaffBranch(user, requestedSlug): a barista
       always gets their own branch and ?branch= is ignored; an admin picks
       any.

     Route handlers (same pattern as the PDF route: 401 / 404, Cache-Control: 
     private, no-store)

     - GET /api/orders/[id]/status
     - GET /api/barista/queue?branch=<slug> (401 signed out, 403 customer, own
       branch only for baristas)

     UI

     - src/hooks/use-polling.ts: 10s interval, pauses while the tab is hidden,
       refetches on return, stops when told (final status), and keeps the last
       good data on a failed request.
     - src/components/orders/:
       - order-tracker.tsx (client): steps as an <ol> with aria-current="step",
         mascot slides along the steps, a role="status" line announces changes,
         ding on change. Keeps data-testid="order-status". Cancelled shows a
         notice instead of the path. Polling stops at a final status.
       - tracker-cup.tsx: empty at Received, fills during Brewing, full
         afterwards.
       - HermesMascot: optional flapping prop wraps the wing paths in a group
         with a CSS animation.
       - All motion is off under prefers-reduced-motion.
     - order-details.tsx: tracker replaces the status line. "Thank you" shows
       only to the order's owner. Adds the receipt on screen in an
       open-by-default <details> below the items; existing cards and links stay,
       so current tests still apply.
     - /barista (src/components/barista/): queue-board.tsx (client) groups into
       Received, Brewing, Ready for pickup, Out for delivery. Each card shows
       code, customer, items, note, pickup/delivery, a Scheduled badge with

       - queue-toast.tsx: small aria-live toast plus play("ding"). The first

       - Admins get a branch switcher. A barista with no branch gets a polite

     - /barista/stock: products and ingredients (base, milk, syrup, topping)

       ingredient says why.
     - Remove StaffPlaceholder from /barista; /admin keeps using it.
