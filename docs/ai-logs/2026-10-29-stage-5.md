  Cart

  - src/lib/cart.ts (pure logic):
    - Each item is { id, kind: "custom" | "product", productSlug? , config?, 
      quantity }.
    - The cart never stores prices. It works them out from the catalog each time
      it's shown.
    - Functions to add, change quantity, remove, replace (for edits), merge a
      guest cart into an account cart, and price the cart (marking anything sold
      out at the chosen branch).
    - Adding an identical item increases its quantity instead of adding a new
      line, up to the existing limit of 20.
  - src/lib/validation/cart.ts: Zod rules for the cart. Anything invalid found
    in localStorage is dropped quietly.
  - src/components/cart/cart-provider.tsx and the useCart hook:
    - The cart lives in localStorage (key hx_cart) and stays in sync across
      browser tabs.
    - When a guest logs in, their cart is sent to the server, merged and saved.
      After that, changes are saved shortly after each edit.
    - On logout the cart is cleared from this device, so the next person on it
      doesn't see it.
  - src/server/cart/actions.ts: a syncCart server action. It requires a session,
    checks the cart with Zod and merges it.
  - /cart page (public):
    - Each item has its summary, a quantity stepper, Edit (custom drinks only,
      opens /build?edit=<id>) and Remove.
    - Totals show the subtotal, plus a note that delivery costs ₱49 and is free
      at ₱800 or more.
    - A checkout button and an empty-cart message.
    - A count badge on the cart in the header and on the mobile tab.
  - Wiring "Add to cart":
    - On /menu, signature drinks and pastries are added as products.
    - In the builder's review step, the drink is added as a custom drink.
    - With ?edit=, the builder loads the drink from the cart (in the browser)
      and the button changes to "Update cart". This replaces the Stage 4 TODO in
      start.ts.

  placeOrder (src/server/orders/actions.ts)

  1. Check the session, then check every input with Zod. Any price sent by the
     browser is dropped.
  2. Check the branch is active and offers the chosen pickup or delivery.
     Re-check ASAP or the slot against the server's own clock.
  3. For each item:
     - Look up the product's price, or recompute the custom drink with
       calculateDrinkPrice.
     - Reject anything sold out at the branch, inactive, or out of season.
     - Snapshot the name, config, unit price and line total.
  4. Calculate totals with calculateCartTotals (the delivery fee rule is already
     there).
  5. Make the code with src/lib/order-code.ts: HX- plus 4 random characters,
     skipping look-alikes such as 0/O and 1/I. If a code is already taken, try
     again.
  6. Save the order, its items and a first status event of received in one
     atomic step (db.batch).
  7. Return the order id. The browser then clears the cart.
