     Stage 4 — Coffee Builder (/build)

     Context

     Stages 0–3 shipped the shell, auth, catalog and calculateDrinkPrice().
     /build doesn't exist yet: the nav, hero, and menu "Customize" links all
     point to it. This stage builds the core feature from PLAN §5: a
     step-by-step builder with an animated cup (pour → stack → mix), a live
     price, undo/reset, "Surprise me", sold-out handling per branch, and prefill
     from a signature drink.

     Your decisions: use ?from=<slug> (and still accept ?drink=). The builder
     E2E test skips when there's no database (same as the menu tests). Reset
     goes back to where you started (the signature recipe or an empty cup), and
     you can undo it.

     Branch: git checkout -b stage-4-builder from main.

     New dependency

     - motion (Motion, formerly Framer Motion). PLAN §9 already lists it for the
       pour, stack and mix animations, but it isn't in package.json yet. Only
       the builder cup imports it, so other pages don't get any bigger.
     - No other new packages. Sliders are native <input type="range">, which
       already works with the keyboard and screen readers. Option pickers are
       native radio buttons and checkboxes styled with Tailwind, so we don't
       need a new shadcn primitive.

     State design (src/lib/builder/, pure, ≥90% coverage)

     state.ts: types, reducer, selectors
     type StepId = "cup" | "base" | "milk" | "sweetener" | "toppings" |
     "review";
     type BuilderDraft = {            // DrinkConfig, but base/milk may be 
     unchosen
       size: DrinkSize; temperature: DrinkTemperature; iceLevel?: AmountLevel;
       base: string | null; shots?: number;
       milk: string | null; milkAmount: AmountLevel;
       sweetness: SweetnessLevel; syrups: string[]; toppings: string[];
       name: string; signature?: string;
     };
     type BuilderState = {
       draft: BuilderDraft;
       start: BuilderDraft;        // the starting point that Reset returns to 
     (empty cup or signature recipe)
       past: BuilderDraft[];       // undo stack, capped at 50
       step: StepId;
       quantity: number;           // 1..MAX_LINE_QUANTITY, not part of undo
       lastEdit: EditKind | null;  // lets the cup know what to animate ("base",
     "milk", "topping"…)
     };
     - Actions: setSize, setTemperature, setIceLevel, setBase, setShots,
       setMilk, setMilkAmount, setSweetness, toggleSyrup, toggleTopping,
       setName, setQuantity, next, back, goToStep, undo, reset, load (used by
       Surprise me).
     - The reducer is reduceBuilder(state, action, rules). rules comes from the
       catalog: each base's included shots and which bases can't be served hot.
     - Rules the reducer enforces (invalid actions change nothing):
       - Iced sets iceLevel to "regular". Leaving iced removes it.
       - Hot isn't allowed with Cold Brew, and Cold Brew isn't allowed while
         Hot.
       - Choosing a base sets shots to that base's included shots, or removes
         shots if the base takes none. Shots stay between 1 and 4.
       - Syrups max 3, toppings max 5, no duplicates. Toggling a selected item
         removes it.
       - Name is trimmed and limited to 40 characters.
     - Every change to the drink pushes the previous version onto past. Typing a
       name doesn't add one undo entry per letter: consecutive setName edits
       share one entry. Undo pops from past. Reset pushes the current drink and
       goes back to start. Stepping between screens isn't undoable.
     - You can only move forward when the step is complete: canAdvance, with
       Base needing a base and Milk needing a milk. goToStep only allows the
       furthest reachable step or earlier ones.
     - Selectors:
       - toDrinkConfig(draft) returns a DrinkConfig, or null if no base is
         chosen yet. It uses "none" for an unchosen milk so the price shows
         early, and turns an empty name into undefined.
       - furthestStep, STEPS (ids and labels).
     - draftFromRecipe(recipe, slug) turns a signature recipe into a draft
       that's still marked as that signature.

     catalog.ts: toBuilderCatalog(snapshot) builds what the client needs: active
     options grouped by kind (slug, name, price, color, included shots), sizes
     and temperatures with their prices, the PricingCatalog, and the signature
     recipes. It drops inactive ingredients.

     src/lib/catalog.ts (addition): soldOutIngredientsByBranch(snapshot) returns
     Record<branchSlug, ingredientSlug[]>. It works like soldOutSlugsByBranch,
     so switching branches is instant here too.

     random.ts: randomDrink(builderCatalog, unavailable: Set<string>, rng = 
     Math.random). It picks only from options that are available at the branch,
     follows the same rules (no hot Cold Brew, ice only when iced, shots only
     for espresso bases, up to 3 syrups, up to 5 toppings), and always passes
     calculateDrinkPrice. The random-number function can be passed in, so tests
     get the same "random" drink every time.

     visual.ts: pure functions the cup uses, all tested:
     - cupLayers(draft, catalog) lists the liquid layers (base, milk, syrup
       tint), each with its color and height share. Base height depends on
       shots; milk height depends on the amount.
     - mixColor(layers) averages the layer colors, weighted by height, into one
       hex color.
     - toppingVisuals(toppings) sorts each topping into foam, drizzle, sprinkle
       or bottom pieces (pearls, jelly, nata).
     - iceCubeCount(level).

     Shared controls:
     - OptionGroup is a fieldset with styled radio buttons. Each option shows
       its price ("+₱20"). Sold-out options are disabled and labeled "Sold out
       at this branch". With Hot selected, Cold Brew is disabled with the hint
       "Served iced or blended only".
     - ChipGroup is a set of checkboxes. When the limit is reached, a counter
       says something like "3 of 3 syrups" and the unchosen chips are disabled.

     Cup animation (Motion, transform and opacity only, for 60fps)

     - Every liquid layer is a motion.rect that grows upward (scaleY from the
       bottom). When lastEdit adds a liquid, a pour stream (motion.rect) drops
       from the top for about 0.6 s, then the new layer rises and settles on top
       of the others.
     - With 2 or more liquids, a mix runs about 0.4 s later: a swirl path
       rotates and fades, and a full-height rect in mixColor fades in over the
       separate layers. "Mix again" replays it.
     - Toppings fall in from above with a spring: foam as a soft cap, drizzle as
       wavy lines, sprinkles as dots, and pearls, jelly or nata settling at the
       bottom.
     - Iced shows cubes that bob slightly. Hot shows steam. Blended shows a
       thicker texture pattern and a domed top.
     - The cup scales with size: 12oz, 16oz and 22oz get different heights.
     - Reduced motion: if useReducedMotion() is true, the cup is drawn in its
       final mixed state with no animation.
     - The SVG has role="img" and an aria-label that describes the drink, for
       example "16oz iced latte with oat milk, mixed".
     - Sound: calls play("pour") and play("clink") through the existing
       useSound() hook. It plays nothing until the audio files arrive in
       Stage 8.

       - ?edit=<cartItemId>: there's no cart yet, so it leaves // TODO(Stage 5)
         and shows an empty cup with a note.
       - Product cards and featured drinks switch to /build?from=<slug>. Their

         builder uses branchCookieString (instant, just like the menu).
       - If anything in your drink is sold out at the chosen branch, Review
         lists it.
       - The server will check prices and stock again at checkout in Stage 5.
     - Keyboard and screen readers: native inputs throughout; visible focus
       rings; an aria-live region that announces things like "Oat milk added.
       ₱160."; Undo, Reset and Mix again are buttons with clear labels.

     Builder cup: the finished drink fills to the brim

     Context

     Right now the cup never fills up. Liquid heights are fixed fractions of the
     cup: a latte with regular milk reaches about 70% of the cup, a black
     coffee 72%, and so on. That leaves a big empty gap under the rim, so the
     drink looks half-poured. You want the finished drink to end right at the
     brim.

     PR #5 is still open on stage-4-builder, so this goes on that branch and the
     Vercel preview updates by itself.

     Behaviour

     - While building: nothing changes. The base pours in to about half the cup,
       as now, so you still see it rise.
     - Milk chosen (any milk, including "No milk"): the drink counts as
       complete, and its liquids rise to the brim. The cup ends just under the
       rim at 97% of the height, so the rim line stays clean.
       - The proportions stay meaningful: light, regular or extra milk changes
         how much of the cup is milk and how much is coffee, and extra shots
         make the coffee part bigger.
       - Syrups stay as a thin layer at the bottom. Adding one later shrinks the
         others a little, so the total stays at the brim.
     - Foam toppings (Cold Foam, Sea Salt Cream): in a real cup the foam is part
       of the fill. The liquid sits lower and the foam finishes at the brim, so
       the top of the drink is always at the rim.
     - Whipped cream: sits on the brim and rises above it as a dome, like a real
       frappe. It's already drawn outside the glass clip, so it isn't cut off.
     - The growth to the brim uses the existing height animation, so it rises
       smoothly. With reduced motion it jumps straight to the end state.

     Changes

     - src/lib/builder/visual.ts
       - Add export const BRIM_SHARE = 0.97.
       - Change cupLayers(draft, catalog, top = BRIM_SHARE):
         - build the layers exactly as now;
         - if draft.milk !== null (the drink is complete), scale every share so
           the total equals top. This keeps the proportions.
         - If the milk isn't chosen yet, the shares stay as they are now.
       - Add foamReserve(toppings, cupHeight). It returns how much of the cup
         the foams take: number of foams × FOAM_THICKNESS ÷ cup height.
     - src/components/builder/builder-cup.tsx
       - Compute the toppings and height before the layers, then call
         cupLayers(draft, catalog, BRIM_SHARE - foamReserve(toppings, height)).
       - Nothing else changes: the surface, the mix overlay, ice, the foam
         stacking and the whipped cream position all follow from the new total.
