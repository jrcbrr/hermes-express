     Stage 7: Admin area

     Context

     Admins currently see a placeholder at /admin. Stage 7 (P0/P2) gives them
     orders, menu, builder options, customers and per-branch summary cards.
     Everything is authorized on the server. Charts stay in Stage 9, promos and
     the points ledger in Stage 8.

     Setup (first, after "go")

     1. main is already pulled. Delete preview/stage-1-design from Neon (oldest
        preview; PR #2 merged). Only that one branch. The project is at 10
        of 10.
     2. git switch -c stage-7-admin. Keep the untracked receipts-part-1.md out
        of commits.
     3. Delete the stage-7-first-steps memory and its index line.

     Shared server code (src/server/admin/)

     Every action starts with requireRole(["admin"], <path>), then Zod, and
     returns { ok: true } | { ok: false, message }. Form actions return field
     errors like updateProfile.

     Reuse rather than rewrite:
     - requireRole (src/server/auth/session.ts). Better Auth has no cookie cache
       configured, so a role change applies on the user's next request.
     - canTransition / nextStatuses (src/lib/order-status.ts).
     - setSoldOut (src/server/barista/actions.ts) already lets admins act on any
       branch and clears the catalog cache. The admin menu calls it and reuses
       StockToggle, with no duplicate action.
     - profileSchema, normalizePhPhone, toFieldErrors
       (src/lib/validation/auth.ts), pesosToCentavos, formatPeso
       (src/lib/money.ts), drinkConfigSchema (src/lib/validation/drink.ts),
       MANILA_TIME_ZONE and midnight helper (src/lib/schedule.ts),
       updateTag(CATALOG_CACHE_TAG), loadCatalog, getOrderForUser (admins can
       already open /orders/[id]).

     Pages and actions

     Layout: src/app/admin/layout.tsx, src/components/admin/admin-nav.tsx
     Sidebar on desktop. On mobile, a drawer built on native <dialog> (focus
     trap and Esc built in, no new dependency) above the bottom tabs. Links:
     Overview, Orders, Menu, Ingredients, Customers. No Promos link until Stage
     8. Remove the StaffPlaceholder use from /admin.

     /admin: summary cards
     Pure src/lib/admin-summary.ts plus getTodaySummary(). Per branch and
     overall: today's orders, revenue, average order value. "Today" is the
     Manila day. Cancelled orders are excluded from all three; Cash on Delivery
     orders count, because an admin wants the day's sales, not only collected
     money.

     /admin/orders: updateOrderStatus
     Filters in the URL (?branch=&status=&date=), so they survive refresh and
     can be linked. 25 per page, newest first. The dropdown offers only
     nextStatuses(). Move the single-statement "update and write event" SQL out
     of advanceOrder into a shared src/server/orders/transition.ts, used by
     both, with advanceOrder's behaviour and tests unchanged.

     /admin/menu (+ /new, /[id]): createProduct, updateProduct, setProductActive
     - Name, description, price (typed in pesos, stored as centavos), seasonal +
       from/to dates, active/hidden, per-branch sold-out.
     - Dates are whole Manila days, with the end date inclusive. Turning
       seasonal off clears both dates, because isAvailableNow reads the dates
       and would otherwise keep hiding the item. From must not be after To.
     - Slug is generated at creation and never edited: photos, carts and recipes
       refer to it. Duplicates get -2. Type is also fixed after creation.
     - Signature drinks need a recipe, or they fall out of pricing and the
       Hot/Iced/Frappe groups. The form has a recipe section (size, temperature,
       base, milk, syrups, toppings), validated with drinkConfigSchema and
       checked against real, active ingredient slugs.
     - New products have no photo: no upload in this stage. MenuPhoto is checked
       and given a neutral placeholder if it can't handle an empty image.
     - No delete: hiding keeps old orders and reports intact.

     /admin/ingredients: updateIngredient
     Grouped by kind. Name, price, colour (<input type="color">, server checks
     #RRGGBB), sort order, active. Edits only; the brief doesn't ask for
     creating options.
     Guard: the last active option of a required kind (size, temperature, base,
     milk) can't be switched off, because the builder would have no valid drink.
     Editing an ingredient price doesn't change a signature's menu price (Stage
     3 decision); the page says so.

     /admin/customers (+ /[id]): updateCustomer, setUserRole, adjustPoints
     - Search name, email or phone (a typed 0917… is normalized to match stored
       +639…; % and _ are escaped). All users are listed, including staff, since
       this is where roles are managed. 25 per page.
     - Detail shows the profile, role, points and orders linking to
       /orders/[id]. Email is read-only.
     - setUserRole: a barista must have a valid branch; any other role clears
       it. An admin can't change their own role, so the last admin can't lock
       themselves out.
     - adjustPoints: whole non-zero delta plus a required note. A single SQL
       update with points_balance + delta >= 0, so the balance can't go
       negative. Then it calls the hook.
     - Hook: src/server/points/ledger.ts, recordPointsAdjustment({ userId, 
       delta, note, adminId }). A tested no-op until Stage 8 adds the
       points_ledger table. No schema change or migration in this stage.

     Tests

     - Unit: one *.test.ts per action file, using the mocked-db pattern from
       src/server/barista/actions.test.ts. Each action is tested for: customer
       and barista rejected with no write, signed-out rejected, bad input, happy
       path, plus the guards above. Pure helpers and queries too, keeping the
       90% gate.
     - Component: admin nav and drawer, product form, role form.
     - E2E e2e/admin.spec.ts: admin logs in, changes a price, /menu shows it; a
       customer is turned away from /admin. Desktop and mobile run in parallel
       on one database, so each uses its own product (Banana Bread, Ensaymada),
       neither used by other specs, and restores the price in finally. Skips if
       DATABASE_URL or SEED_ADMIN_* is missing, as CI still has no database.

     Closing

     Small prefixed commits, roughly one per area. npm run lint, typecheck,
     test:coverage, build, plus test:e2e locally; fix failures. Update
     CHANGELOG.md, docs/AI_LOG.md, docs/ARCHITECTURE.md, and the decisions in
     docs/PLAN.md §13. Push, gh pr create with the template, then list what to
     check on the Vercel preview, at 375px and 1280px.

     Known limits

     - Points adjustments made before Stage 8 change the balance but leave no 
       history; the note is discarded by the no-op hook. Stage 8 must make the
       balance update and ledger write one statement, as advanceOrder does.
     - /admin/promos stays unbuilt until Stage 8, and charts until Stage 9.
